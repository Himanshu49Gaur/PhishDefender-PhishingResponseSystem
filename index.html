// system design
Detection Pipeline

Five independent layers combine into a single weighted threat score. Click each step to expand.

01
Gmail DOM Extraction
content.js reads the open email from Gmail's dynamic SPA DOM using MutationObserver and multiple CSS selector fallbacks.
JavaScriptMV3 ExtensionMutationObserver

Gmail wraps all outbound links as google.com/url?q=... redirects. The content script decodes these using URLSearchParams to expose the real destination before analysis. DOM extraction is resilient to Gmail UI updates via ordered selector fallbacks.

02
Email Header Analysis
Checks SPF, DKIM, DMARC authentication results and Reply-To mismatches. All three failures together trigger a +15 bonus score.
SPFDKIMDMARCemail_parser.py

Header analysis can yield up to 53 points. Individual auth failures score 10 pts each — sufficient to flag but not block. The combined "all three fail" bonus reflects that this pattern is a much stronger signal than any single failure, as many legitimate small businesses also fail individual checks.

03
LightGBM ML Classifier
Two GPU-trained models — one for email text (TF-IDF + 13 hand-crafted features) and one for URL structural features (50 columns).
LightGBMTF-IDF98.9% F1164K samples

Email model uses a 5,013-wide sparse matrix: 5,000 TF-IDF bigram features stacked with 13 engineered signals (URL count, capital ratio, exclamation density, keyword hits…). URL model uses 50 structural features including 3 interaction terms. Combined score is 60% email + 40% URL.

04
Threat Intelligence APIs
VirusTotal scans each URL across 70+ antivirus engines. AbuseIPDB checks sender IP reputation and Tor exit node status.
VirusTotalAbuseIPDBthreat_intel.py

VirusTotal uses an async polling flow: submit URL → receive analysis ID → poll until status = "completed". Free tier allows 4 req/min — a 15s sleep between URL scans respects this. A confirmed malicious URL alone contributes 30 points, making it nearly decisive.

05
Rules Engine + Report
Weighted signals sum to a 0–100 threat score. Malicious or suspicious emails trigger a PDF SOC-style incident report with full IOC list.
rules_engine.pyReportLab PDFIOC extraction

The rules engine makes signal combinations explicit and auditable — unlike pure ML verdicts. The PDF report mirrors real SOC incident report structure: verdict banner, IOC table, ML confidence scores, triggered rule trace, and recommended actions. Only generated for malicious/suspicious verdicts.

Get Running in 5 Steps
STEP 01
Clone the repo
git clone https://github.com/Himanshu49Gaur/PhishDefender-PhishingResponseSystem.git
cd PhishDefender-PhishingResponseSystem
STEP 02
Install dependencies
pip install -r requirements.txt
STEP 03
Add API keys
cp .env.example .env
# Edit .env:
# VIRUSTOTAL_API_KEY=...
# ABUSEIPDB_API_KEY=...
STEP 04
Start the backend
python app.py
 → http://127.0.0.1:5000
STEP 05
Load Chrome extension
chrome://extensions/
                            → Enable Developer Mode
                            → Load Unpacked
                            → Select Extension_Files/
